# 《鹅厂出逃记》俯视场景统一改造说明

> 日期：2026-08-08  
> 状态：方向已确认，待实施  
> 适用范围：序章以外的可操作章节；终章作为演出场景单独处理

## 1. 变更结论

本次将游戏的场景玩法统一为“俯视地图探索 + 空间互动”，但保留每一章自己的核心事件。

- 工厂序章保留侧视玩法，作为移动、互动和翻墙教学。
- 篮球馆、荔枝园、烧鹅店、工业园区、DGUT 校园统一改为俯视地图。
- 终章松山湖继续承担走马灯和结局演出，不强制改成自由漫游关卡；画面保持平面/俯视构图即可。
- 原有投篮、序列解谜、潜行、收集组合和观察内容不删除，改为在统一的俯视场景中触发。

目标体验：玩家先在同一张地图中移动，靠近角色或物件后出现明确的互动提示，完成局部玩法后回到地图继续推进剧情。

## 2. 统一场景交互标准

除工厂序章外，所有可操作场景应具备以下结构：

1. 进入场景后播放开场对话；对话期间锁定移动。
2. 对话结束后进入俯视地图探索状态。
3. 玩家通过虚拟摇杆或键盘方向键移动角色；桌面演示可补充点击地面移动。
4. 靠近 NPC、物件、出口或任务目标时显示上下文提示，例如“交谈”“摘荔枝”“查看”“收集”“离开”。
5. 使用统一的互动动作触发事件，不再让每一章主要流程依赖固定 DOM 热区点击。
6. 互动中的对话或局部玩法锁定地图移动；结束后返回原地图位置。
7. 地图上显示当前目标、进度和出口状态，避免玩家不知道下一步要做什么。
8. 完成章节目标后，通过出口或明确的“继续前行”互动推进下一章。

### 统一需要具备的界面元素

- 场景标题或地点标识。
- 当前目标/状态卡。
- 互动对象的高亮、标签或范围提示。
- 底部操作提示。
- 章节进度或收集计数。
- 对话结束后的返回地图反馈。

## 3. 荔枝园玩法改造

### 3.1 新流程

荔枝园不再是“直接点击树木完成序列”，改为“与老婆婆交谈 → 按要求寻找并摘取荔枝 → 回去交付”。

1. 玩家进入荔枝园，与老婆婆完成开场对话。
2. 老婆婆和指示牌共同给出摘取要求；保留现有顺序 `3 → 1 → 4 → 2` 作为谜题答案。
3. 对话结束后，玩家可以在果园内自由移动，老婆婆、指示牌、五棵荔枝树和出口都位于同一张俯视地图上。
4. 靠近当前目标树时显示“摘荔枝”提示。
5. 玩家触发互动后播放简短摘取反馈，树木进入已摘状态，进度显示为“荔枝 1 / 4”。
6. 摘取正确树木后推进到下一棵目标树，并高亮下一目标或更新提示。
7. 摘错树木时仅提示“这不是老婆婆要的”，不重置已经摘取的进度，避免演示节奏被打断。
8. 四棵目标树全部完成后，回到老婆婆处，靠近并触发“交给婆婆”。
9. 老婆婆完成收取对话后，栅栏门打开，玩家前往出口推进剧情并获得荔枝园印记。

### 3.2 交互规则

- 树木互动必须由玩家主动触发，不能仅靠进入范围自动摘取。
- 只有当前目标树可完成有效摘取；其他树可以显示错误反馈，但不影响已完成进度。
- 交付动作必须在老婆婆附近主动触发，不能在最后一棵树摘下时直接跳过。
- 对话期间、摘取反馈期间和栅栏开启动画期间锁定移动。
- 失败反馈不改变剧情正式出口，玩家始终可以继续完成本章。

### 3.3 荔枝园验收标准

- [ ] 开场对话结束后，玩家可在果园内自由移动。
- [ ] 老婆婆、指示牌、荔枝树和出口都可以在地图上辨认。
- [ ] 当前目标树有明显高亮或上下文提示。
- [ ] 正确顺序仍为 `3 → 1 → 4 → 2`。
- [ ] 每次摘取都会更新树木状态和“已摘荔枝”进度。
- [ ] 摘错不会清空已经完成的进度。
- [ ] 集齐后必须回到老婆婆处交付。
- [ ] 交付后栅栏打开，走到出口才能推进剧情。
- [ ] 印记、章节完成事件、抉择点和下一章跳转保持原有逻辑。

## 5. 技术改造范围

### 5.1 共享能力

在现有 `PlayerController`、`InputManager` 和 `SceneManager` 基础上补齐共享能力：

- 俯视场景边界与基础地图碰撞。
- 统一互动目标数据结构：位置、范围、名称、可用条件、触发回调。
- 统一“靠近目标 → 显示提示 → 按动作键/点击按钮触发”的交互流程。
- 统一场景目标、进度和出口状态显示。
- 统一对话期间的移动锁定与结束后的地图恢复。
- 统一触控和桌面回退输入，确保手机横屏与明天演示都能操作。

### 5.2 场景改造原则

- 不在每个场景内重复实现一套交互热区逻辑。
- Canvas 负责地图、角色和物件表现，DOM 负责可访问的提示、进度和对话 UI。
- 局部小游戏可以复用现有逻辑，但入口和出口必须接入俯视地图。
- 不改变现有剧情分支、印记发放、存档和章节跳转规则。
- 新资源未就绪时允许使用现有绘制占位，先完成玩法和流程验证。

### 6.3 每个俯视场景需要的美术交付物

每个可探索场景至少需要以下资产，不以一张完整插画代替：

- 俯视或接近俯视的可行走地图背景。
- 可行走区域与不可行走区域的碰撞/导航遮罩。
- 可独立定位的 NPC、目标物、出口和前景遮挡层。
- 互动点位置表，包含地图坐标、范围、显示名称和完成后的状态。
- 角色与地图的统一脚底线、缩放比例和安全区。
- 适配 16:9 横屏的裁切规则，保证顶部状态卡、底部操作提示不会遮住关键目标。

现有模板图可以继续作为场景开场、过渡、局部玩法或结局定格背景；真正进入自由移动阶段时，应使用对应的俯视地图版本或拆分后的地图图层。

### 6.4 美术验收标准

- [ ] 进入每个场景时使用对应章节的已产出视觉方向，不再使用与场景无关的通用色块背景。
- [ ] 除工厂外，地图地面能清楚表达角色可走区域、障碍物和出口。
- [ ] 荔枝园至少能辨认老婆婆、五棵目标树、指示牌、栅栏门和出口。
- [ ] 烧鹅店的俯视地图与现有烧鹅店模板/预览保持色调、物件和空间关系一致。
- [ ] NPC 使用现有三视图资产裁切后的透明角色，不显示白底或设定图文字。
- [ ] 角色脚底与地面接触自然，移动时不会漂浮、穿墙或被背景层错误遮挡。
- [ ] 互动目标、进度卡、对话框和底部提示在 16:9 横屏下不压住角色与关键物件。
- [ ] 场景图作为演出背景使用时保留完整构图，作为玩法地图使用时不强行拉伸成俯视效果。

## 7. 实施顺序

1. 先补齐共享俯视场景的移动、碰撞、互动提示和目标状态能力。
2. 以荔枝园作为样板，完成“NPC 对话—移动摘取—回 NPC 交付—出口推进”的完整闭环。
3. 将烧鹅店接入统一的 NPC/物件互动提示，并保留现有潜行逻辑。
4. 将工业园区和校园的固定点击热区改为地图中的靠近互动。
5. 将篮球馆改为俯视球馆入口与投篮点，再嵌入现有蓄力投篮玩法。
6. 最后回归工厂侧视教学和松山湖结局演出，确认它们与统一流程的切换自然。

## 8. 总体验收标准

- [ ] 除工厂序章外，所有可操作章节均使用俯视地图。
- [ ] 各章节进入自由阶段后均可移动角色，而不是只点击固定热区。
- [ ] 主要 NPC、物件和出口均有明确的靠近互动提示。
- [ ] 对话和局部玩法期间移动正确锁定，结束后回到地图。
- [ ] 每章都能看见当前目标或进度，不需要依赖开发者口头说明。
- [ ] 篮球、荔枝、烧鹅、工业园和校园的核心玩法仍然可完成。
- [ ] 篮球失败后领取纪念并继续剧情的逻辑保持有效。
- [ ] 剧情分支、印记、存档、章节完成事件和结局结算不回归失败。
- [ ] `npm test`、`npm run build` 通过，并完成手机横屏与桌面演示冒烟测试。

## 9. 本次明确不做的内容

- 不把工厂序章强行改成俯视。
- 不把松山湖终章改造成完整探索关。
- 不删除各章节原有的投篮、潜行、收集、观察和剧情分支内容。
- 不因为改成俯视而重新设计主线剧情或结局结构。
- 不在本说明阶段提前替换全部美术资源；先以玩法闭环和可演示性为验收重点。
